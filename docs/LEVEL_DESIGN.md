# THE LAST ARK · 底板玩法与关卡设计

> 状态：可运行垂直切片。四关已实现并通过无头自动护航验证；真人双人键盘手感尚未验证。
> 对应代码：`src/levels/**`、`src/game/mission.ts`、`src/game/runtime.ts`。
> 共享契约：`src/shared/contracts.ts` v0.2.0（v0.1 的可选扩展）。

## 1. 设计目标

**一句话：** 两名玩家不能驾驶方舟，只能改变它周围的引力；他们必须让方舟自己走完航程。

四条不可妥协的底线：

1. **不直接控制方舟。** 位置、速度、通关都只由物理与力场产生。
2. **两个玩家都不可替代。** 吸引与排斥方向相反、用途不同；成功路线必须同时用到两者。
3. **失败可解释。** 每次失败都能在画面上找到原因：撞上什么、被什么吞没、从哪里漂出边界。
4. **先可通关，再谈表现。** 每一关都有零输入基线（必须失败，教学关除外）和合法输入通关证据。

表现优先级：**视觉 > 剧情 > 玩法复杂度**。底板阶段只做单屏关卡，不做分支剧情、收集品、战斗或第二套物理。

## 2. 核心玩法底板

### 2.1 操作

| 玩家 | 移动 | 力场（按一次切换） | 颜色 |
| --- | --- | --- | --- |
| P1 · 收束 / CONVERGE | `WASD` | `F` 吸引开 / 关 | 蓝 `#54b6ff` |
| P2 · 划界 / DIVERGE | 方向键 | `Enter` 排斥开 / 关 | 金 `#f1c56d` |

通用：`Space` 开始 / 暂停 / 继续；`R` 从本章开头重试；`M` / `Esc` 打开章节目录；失焦自动暂停并清空按键。

力场是**开关**：按一次开启，再按一次关闭，不需要持续按住。两人可以同时移动、同时施力，也可以随时关闭力场让方舟靠惯性滑行。

运行中会在世界层绘制**预计轨道线**（3.4 秒短时前向积分）。白色虚线是预计航迹；红色端点表示预计撞击/吞没/越界；绿色端点表示预计入港。它只读取快照与关卡数据，不写回模拟。

### 2.2 物理语义（与 `docs/AGENT_PROTOCOL.md` 一致）

- 固定时间步 `1/60 s`；渲染帧率不影响物理。
- 力场公式：`a = s · strength · d / (r² + ε²)^(3/2) · max(0, 1 − r/R)²`
  - `d = 力源 − 受力天体`；`s = +1` 吸引/引力，`s = −1` 排斥。
  - 每个源先限幅到 `maxAcceleration`；合向量乘 `motionResponse`；再限幅到 `maxTotalAcceleration`。
- 半隐式欧拉：先更新速度、再更新位置；速度限幅到 `maxBodySpeed`。
- 方舟与危险天体使用相对运动扫掠圆碰撞；黑洞按中心距离 `consumeRadius` 吞噬。
- 方舟完整碰撞圆进入泊位且速度 `≤ maxEntrySpeed` 才胜利；完整入港但超速只警告，可以港内减速。
- 失败优先级：`consumed > collision > out-of-bounds`；任何失败优先于胜利。

### 2.3 一屏一关

所有关卡共用 `1200 × 720` 逻辑世界，等比留边。关卡之间通过章节卡与 `load-level` 连接，不做滚动镜头。这样：

- 双人同屏合作不会被镜头分开；
- 每一关的构图、危险轮廓和港口都能一次读全；
- 视觉 agent 只需要一个视口适配逻辑。

### 2.4 任务层（v0.2 可选）

`LevelSpec.mission` 是纯数据，不影响物理，只由 `src/game/mission.ts` 解释：

| 脚本 | 用途 | 关键字段 |
| --- | --- | --- |
| `tutorial` | 第 0 关教学步骤 | 无 |
| `planet` | 行星响应提示 | 无 |
| `solar` | 行星共振、太阳冲击波、门锁 | `resonanceZones`、`requiredResonance`、`shockwave`、`gateRequiresResonance` |
| `blackhole` | 伽马喷流 | `jet` |

`FrameSnapshot.mission` 只向 HUD 暴露已经判定好的文本与进度，渲染层不判胜负。

## 5. 第 0b 关 · 会动的世界

### 5.1 体验目标

让玩家第一次意识到：**行星也会被力场推动**。同时引入第一个硬指标：入港速度 ≤ 48。

### 5.2 地图

```text
┌──────────────────────────────────────────────────────────────┐
│        ◉ P1 (300,280)                                        │
│                                                              │
│ ▶ ARK-01 (140,360)      ● 行星 (600,350)        ◎ 告别港      │
│    v = (76,0)              r = 62                 (1050,360)  │
│        ◉ P2 (250,500)     引力环 R = 280           r = 82      │
│                                              ≤ 48 入港        │
│                          ▲ 陨石 (770,560)                    │
└──────────────────────────────────────────────────────────────┘
```

### 5.3 三阶段路线

1. **抬升（x < 480）**：蓝场上提、金场从下推，让方舟在到达行星前进入 y ≈ 210–250 的走廊。
2. **通过（480 ≤ x < 900）**：保持走廊，松开不必要的场；行星会被较强力场轻微推离，这是可见的。
3. **回落与减速（x ≥ 900）**：金场站到船头方向回推，蓝场修正；完整进入绿环且速度 ≤ 48。

允许从行星下方绕行。陨石不在主航线上，但两位玩家的力场都能影响它。

| `ark-01` | (140,360) | 11 | (76,0) | — |

### 6.4 太阳与冲击波

- 太阳是危险天体（碰撞半径 88），同时发出引力（R 430 / 强度 1.1e6 / ε 130 / 源限幅 38）。
- 太阳接受玩家力场，`motionResponse 0.02`：两名玩家在两侧同时施力时，太阳会轻微移动。这是剧情里的“双场合流”，没有额外的按钮或脚本。
- 方舟首次越过 `x ≥ 760` 时触发坍缩：**5 秒后**冲击波从太阳中心以 **60 px/s** 向外扩张；扩张半径追上“太阳中心到方舟”的距离即失败（`consumed`）。
- HUD 显示“冲击波将在 X.X 秒后抵达”。画面上的橙色环即真实判定半径，不是装饰。

### 6.5 门锁

- 四条共振区（半径 90–115）以行星为中心；方舟进入即记录，HUD 行星链点亮。
- `gateRequiresResonance = true`：4/4 之前，冥王星之门显示为金色、标注“共振不足 · 门未开启”，即使完整进入也不获胜。
- 冲击波开始后仍允许回头补录；延迟和波速按“回头还来得及，但会很紧”调校。

- 设计注意：太阳引力会把不操作的方舟拉出弧线，这正是关卡压力来源；自动路线必须持续修正。

## 7. 第 2 关 · 越过银河

### 7.1 体验目标

面对一个**不能被推动**的东西：不要试图战胜它，只需要从它旁边经过。黑洞不是 Boss，是界碑。

### 7.2 地图

```text
┌──────────────────────────────────────────────────────────────┐
│                              ⬡ 银河边缘出口 (1080,170)        │
│                                 r = 60, ≤ 65                 │
│                          ┃ 伽马喷流柱                         │
│                          ┃ x = 640 ± 72                      │
│ ▶ ARK-01 (130,420)       ┃     ◉ SAGITTARIUS A* (640,360)    │
│    v = (52,−3)           ┃       r = 48, consume = 62        │
│                          ┃       引力 R = 520                │
│                                                               │
│        ▲ debris (420,610)   ▲ (760,620)   ▲ (1020,610)       │
└──────────────────────────────────────────────────────────────┘
```

### 7.3 机制

- **不可推动**：黑洞 `receivesPlayerFields = false`、`motionResponse = 0`、`receivesGravity = false`。玩家把节点移过去也不会产生力；提示只说一次：“不要推它。它不在你们的力场里。”
- **视界**：`consumeRadius = 62`。方舟中心进入即 `consumed`；画面上的红色虚线圈就是判定线。
- **引力**：R 520 / 强度 1.25e6 / ε 120 / 源限幅 34。顶部走廊会被持续向下拉，两人必须持续向上修正。
- **伽马喷流**：x = 640 ± 72、y = 360 ± 250 的柱状区域；周期 6 s，开启 1.8 s；开启期间方舟在柱内获得 38 px/s² 的向上加速度。它既是推进窗口，也是画面节拍。
- **残骸**：三颗灰色陨石沿底部漂移，接受玩家力场但不接受黑洞引力（防止它们在开局被吸成不可预测的炮弹）。它们不在主航线上，但低头会撞上。

### 7.4 路线

1. 从左侧抬升，沿黑洞上方 y ≈ 200–240 的潮汐走廊通过。
2. 在 x ≈ 640 处进入喷流柱；喷流开启时借力上升。
3. 从右上方接近出口，减速到 ≤ 65，完整进入绿环。

黑洞引力会持续把方舟拉向中心；玩家必须用蓝场向上拉、金场从下方推。喷流不是必选项，但会让上升段更从容。

### 7.5 参数

| 对象 | 位置 | 半径 | 关键参数 |
| --- | --- | --- | --- |
| `ark-01` | (130,420) | 11 | 初速 (52,−3) |
| `sagittarius-a` | (640,360) | 48 | 静态、不可推动、`consumeRadius 62`、引力 R 520 / 1.25e6 / ε 120 / 34 |
| `debris-01` | (420,610) | 14 | 初速 (14,0)，接受力场，不受引力 |
| `debris-02` | (760,620) | 16 | 初速 (−10,0)，同上 |
| `debris-03` | (1020,610) | 12 | 初速 (−16,0)，同上 |
| `galactic-exit` | (1080,170) | 60 | `maxEntrySpeed 65` |

### 7.6 验收

- 零输入：7.8 s 被视界吞没，`lost / consumed`。
- 自动护航：13.1 s 获胜，入港速度 64.7 px/s（≤ 65；自动路线只在最后约 0.4 s 制动，真人应更早减速）。
- 浏览器实测：喷流开启时柱体高亮、粒子上升，HUD 显示“开启中”与剩余时间；关闭时柱体变暗。

## 8. 第 3 段 · 群星之间（无限模式，设计稿）

> 本轮未实现。以下为可落地的设计约束，供后续开发。

### 8.1 核心

- 无失败压力、无 Boss 条、无倒计时；只有程序化区块、环境危险和发现。
- 每 2–4 个区块至少出现一个可感知变化：新颜色、星云、三合星、旧文明残骸。
- 方舟可以用引力借力，但不需要“通关”；玩家可以随时停下或继续。

### 8.2 发现

| 发现 | 内容 | 触发 |
| --- | --- | --- |

### 8.3 技术方案

- `src/levels/endless.ts` 只导出起始区块；`src/game/universe.ts` 按 seed 生成区块。
- 区块用纯数据描述：恒星、行星、危险区、发现 ID；物理继续复用现有 `BodySpec`。
- 发现卡复用 `NarrativeSpec` + `MissionView`，不新增第二套 UI 协议。
- 需要新增：区块流式加载、距离/光年标尺、发现持久化。不要在底板阶段提前实现。

## 9. 数值验收与调参

### 9.1 自动验证（`tests/levels.test.ts`）

| 关卡 | 零输入结果 | 自动护航结果 | 入港速度 |
| --- | --- | --- | --- |
| `first-contact` | **won** 21.0 s | won 21.0 s（零输入） | 40.0 |
| `moving-world` | lost / collision 6.4 s | **won 13.2 s** | 47.7 |
| `solar-exodus` | lost / collision 8.7 s | **won 24.4 s** | 35.4 |
| `beyond-horizon` | lost / consumed 7.8 s | **won 13.1 s** | 64.7 |

自动护航是闭环控制器：每 tick 读取快照、放置节点、开关力场；测试把每一帧输入记录下来，从干净运行时重放，四关都能在**相同 tick** 复现 `won`。这证明：

- 通关只使用了合法输入；
- 物理是确定性的；
- 不存在直接改位置/速度/阶段的作弊路径。

### 9.2 调参杠杆

| 症状 | 优先调整 |
| --- | --- |
| 方舟过早撞障碍 | 降低初速 5–10；扩大走廊；降低障碍引力强度 |
| 入港总是超速 | 提前 150–200 px 开始减速；提高 `maxEntrySpeed` 3–5；扩大港口 |
| 玩家力场太强、难以精细操作 | 降低 `strength` 10–15%；降低 `maxAcceleration`；保持半径不变 |
| 行星完全推不动 | 提高 `motionResponse` 到 0.2–0.25，或提高力场在近距离的强度 |
| 冲击波永远追不上 | 降低 `delaySeconds`；提高 `speed`；把 `triggerX` 提前 |
| 冲击波太苛刻 | 提高 `delaySeconds`、降低 `speed`、扩大门锁允许时间 |

### 9.3 尚未验证

- **真人双人同键盘手感**：WASD + F 与方向键 + Enter 同时按下的硬件冲突、手部姿势、提示可读性。
- **难度曲线**：自动护航证明“存在解”，不证明“人类觉得有趣”。
- **帧率/性能**：Edge headless 截图正常；未在低端机、DPR 2、窄窗口下测帧率。
- **移动端**：无触摸操作；窄窗口只显示“建议横向全屏游玩”。

## 10. 后续扩展（按优先级）

1. **真人试玩与容错回放**：按协议做 ±12 tick 的关键施力偏移测试，至少三组。
2. **检查点**：第 1、2 关失败后从最近行星/走廊入口重试，而不是整关重来。
3. **九道共振多屏版**：把当前四锚点扩展为 2–3 屏；镜头跟随或分段加载。
4. **节点牺牲与重组**：黑洞关的叙事机制；需要玩家可被吞噬后重生的状态。
5. **双场合流推太阳**：已在物理上成立（太阳 `motionResponse 0.02`），需要 HUD 位移槽与一次性上限。
6. **无限模式**：最后做，且必须复用现有物理与卡片协议。
