# Agent 2：视觉渲染协议与四小时计划

适用契约：`src/shared/contracts.ts` **v0.1.0**；状态与所有权遵循已冻结的 [三 Agent 接口协议](AGENT_PROTOCOL.md)。本文件是本轮三 Agent 协作的实施配套文档；当前只完成协议与计划，尚未实现或测试渲染器。用户没有提供可读取的参考图，不声称还原参考图。

## 1. 视觉目标与边界

在 TypeScript + Vite + Canvas 2D 中建立清晰、有太空氛围、能立即辨认交互关系的基础画面。视觉投入优先于剧情篇幅与玩法复杂度，但必须保留真实力场边界、碰撞可读性、双人控制与稳定通关底线。通过色彩、留白、层次、线宽和字体建立氛围。

- P0：基础几何天体、正确坐标与比例、真实力场圈、方舟朝向、速度/入港阈值、状态、双人按键提示、缩放和重试。
- P1：联调通过后才加入稀疏静态星空、低对比度装饰弧线、少量稳定径向渐变。装饰不能伪装成轨迹预测或扩大技能边界。
- 本轮不引入外部素材、音乐、粒子系统、复杂动画、React、Three.js 或 PixiJS。

## 2. 文件所有权与接口

- Agent 2 独占 `src/render/**`，从 `src/render/index.ts` 导出 `createRenderer(canvas: HTMLCanvasElement): CanvasRenderer`。
- Agent 2 独占 `src/style.css`，维护画布容器、背景、排版和禁止页面滚动的样式；Agent 3 仅在 `src/main.ts` 导入，样式改动需求交 Agent 2 处理。
- Agent 3 独占 `src/main.ts`：RAF、固定步长累计器、键盘、命令、resize/可见性监听、生命周期。渲染器不另开动画循环、不绑定游戏按键。
- Agent 1 独占关卡与叙事；渲染器消费传入的 narrative，不自行加载关卡或硬编码规则。
- 主 Agent 管理共享契约。缺字段先报告，不单方面增删契约或用类型强转掩盖版本不匹配。
- 本轮实际写入范围仅为 `docs/RENDER_BRIEF.md`；上述源码所有权是后续实施约定。

`createRenderer` 获取 Canvas 2D 上下文；不可用时明确抛出启动错误，由主入口展示。工厂不创建游戏运行时。严格实现共享方法：

- `resize(cssWidth, cssHeight, devicePixelRatio)`：更新显示与后备像素尺寸、视口；尺寸为零时跳过绘制，避免除零。
- `render(frame: RenderFrame)`：读取完整快照并画一帧。
- `dispose()`：释放自己创建的缓存和引用；外部监听由创建它们的主入口移除。

主入口调用顺序：创建运行时和渲染器 → resize → 每帧处理输入与固定步长 → snapshot → 唯一一次 drainEvents → render。以后其他消费者需要事件时，由主入口分发同一批次，不能再次 drain。

## 3. 快照、事件与状态消费

### FrameSnapshot

- 默认世界 **1200 × 720**，但以 `snapshot.world` 为真实尺寸来源。位置单位为逻辑像素，速度为 px/s。
- `phase` 是唯一状态来源：ready 显示“部署观察者 / Space 发射”；running 显示运行；paused 显示暂停；won/lost 显示结果与 R 重试。ready 允许玩家重定位，但展示层不移动方舟。
- `PlayerView.fieldActive` 表示实际施力状态，区别于输入按键意图；非 running 必须为 false。ready 允许走位，但不显示开启的力场范围；paused/won/lost 同样关闭技能圈。所有状态仍显示键位与能力说明；只有 running 且 fieldActive=true 才画对应技能圈。
- running 中用 previousPosition→position 插值，alpha 限制在 [0,1]；ready/paused/won/lost 强制用 position（alpha=1）。玩家实体和技能圈使用相同绘制坐标。
- 方舟按 velocity 朝向绘制。近零速度沿用本 run 最近有效朝向，首次默认朝右；三角顶点位于 body.radius 碰撞圆内，不能画出明显更大的实体。
- 玩家、天体、技能、港口与吞噬中心的半径均读取快照。缩放不改变物理尺寸。
- HUD 速度来自 arkSpeed，建议 1 位小数；并列显示 dock.maxEntrySpeed，说明“整船进入绿环，速度 ≤ 阈值”。
- dockOverspeed 只显示“速度过高，请减速”，不判定失败；目标绿环精确对应 dock.radius。
- failureReason 映射 narrative.failure；胜利显示 narrative.success；ready 使用精简 briefing；hintId 查 narrative.hints，不自行计时触发教程。

渲染器只读输入，禁止修改位置、速度、phase、tick、关卡或输入。UI 不判胜负，不维护第二份游戏状态；画面仅呈现运行时已做出的判断。

### RenderFrame 与 GameEvent

- events 是当帧事件批次，按 `(runId, eventId)` 去重，用于可选一次性提示。关键状态必须能仅靠 snapshot 重建，不能依赖曾收到某条事件。
- snapshot.runId 变化时，清空事件去重、提示寿命、缓存朝向、插值关联、背景/关卡缓存与未来尾迹缓存。tick=0 不能代替 runId 判断。
- 忽略 runId 与快照不匹配的旧事件。去重集合只保留当前 run，更换 run 立即释放，避免无界增长。
- visualTimeSeconds 仅作视觉时钟，禁止用于物理、入港或教程规则。P0 静态绘制；P1 如增加轻微脉冲，也在 paused/won/lost 冻结。
- 暂停/重试后的任何主体位置来自最新快照，不能继续播放上一局插值或旧位移。

## 4. 世界视口、DPR 和绘制顺序

等比 letterbox：`scale = min(cssWidth/world.width, cssHeight/world.height)`，将剩余宽高各取一半作为居中偏移。后备画布尺寸为 CSS 尺寸×DPR 取整；绘制变换包含 DPR、scale 与偏移。以单位变换清除整个后备画布，再裁剪世界矩形，防止残影和越界绘制。窗口比例不能把圆拉成椭圆。

可明确采用有效 DPR=`min(传入DPR, 2)`；上限只影响清晰度，不改变坐标或规则。主入口仍传真实 DPR。零尺寸跳过；极窄窗口提示“建议横向窗口游玩”，不偷偷改世界尺寸。

绘制顺序：背景/可选静态星点 → 世界边界/港口 → 开启的真实技能圈 → 危险大型星体/危险中心 → 陨石/方舟 → 玩家/P1P2 标签 → HUD/提示/状态。

HUD 优先利用 letterbox 留边；不足时在世界边缘用紧凑文字配轻薄深色底，避免遮航道的大面板。始终显示世界边框。操作行可拆两行：`P1 WASD / F 吸引 · P2 ↑↓←→ / Enter 排斥 · Space 开始/暂停 · R 重试`。剧情限制 1–2 行，操作开始后让位于地图。

## 5. 色彩与几何规范

- 背景近黑蓝 `#071019`，正文 `#DCE8F0`，次级文字 `#8294A3`；避免高亮噪点。
- Attractor 蓝色 `#5AAEFF` 圆，标记 P1/F；开启时低透明圆盘和清晰细边显示 field.radius，可用少量静态向心短箭头。
- Repulsor 金色 `#F6C85F` 圆，标记 P2/Enter；真实 field.radius 圆配向外短箭头。重叠区不暗示额外规则，两个边界仍可分辨。
- 方舟白色 `#F5F7FA` 三角；不画改变体积理解的实体尾焰，不做轨迹预测。
- 陨石灰色 `#929CA6` 圆配细暗边；视觉不自行移动它。
- 危险星体紫色 `#9B78D7` 圆，实体边缘对应 body.radius；黑洞如有 consumeRadius，明确标内圈。气氛渐变不得伪装成另一条碰撞边界。
- 港口绿色 `#6EE7A1` 细环与 PORT 标签，半径精确；超速用文字辅助，不只用颜色。
- 类别同时借助文字、形状或方向辨认，避免只靠颜色。

P1 星空按已冻结协议使用 levelId 的稳定字符串哈希确定性生成，无需读取模拟器 seed 或新增共享字段。静态流线最多是远离主体的低对比装饰弧线，不能看起来像实时力场积分线；优先省略以免误导。

## 6. Mock 先行与联调

Agent 2 在 `src/render/**` 建仅开发使用的类型化 mock，完整满足 v0.1.0，不使用不完整对象强转。mock 覆盖两个玩家、方舟、危险星体、可动陨石和港口；不成为生产关卡或游戏状态来源。

Agent 3 提供真实 createGame、snapshot、事件副本、alpha、wall time、narrative 与 resize。Agent 2 交付工厂与三场景截图。**T+90 分钟前必须接上真实引擎**，之后以真实快照复现问题。

接口上报格式：`版本 + 复现快照 + 期望显示 + 当前缺口 + 最小改动建议`。在统一版本前不添加未定义字段。

## 7. 四小时节点（从共同开工 T0 起算）

- **00–15 分钟：** 确认契约、尺寸、颜色语义和所有权；报告缺口；确定工厂导出，不等待最终关卡。
- **15–45 分钟：** 完成 resize/DPR/letterbox 与 P0 实体、场圈、速度、状态；交付 mock 画面。
- **45–70 分钟：** 完成三场景截图、宽高比与双场重叠检查；与策划核对位置和文案长度。
- **70–90 分钟：** 接真实快照与事件，检查所有主体位置；90 分钟未接通则立即停止 P1。
- **90–135 分钟：** 实际操作开始、暂停、双技能、失败、重试和胜利；只调整可读性，不擅改物理参数。
- **135–180 分钟：** P0 全通过后才添加星空/渐变；检查 16:9、近4:3、较窄窗口与 DPR 1/2。
- **180–210 分钟：** 功能冻结，修遮挡、缩放、暂停与缓存；交付最终截图及实测记录。
- **210–240 分钟：** 配合全流程试玩、构建与发布，只修阻塞；把已测/未测项交主 Agent 写 README，保留 GitHub 推送和复核时间。

## 8. 三场景截图与实际验收

截图只验视觉，不能替代物理测试。至少保存并复核三组：

1. **部署：** 完整边界、蓝金玩家、左侧方舟、中部危险体、右侧港口、速度与按键可见；文字不遮关键航道。
2. **双场工作：** 两个真实半径技能圈同时开启并重叠；方舟、陨石、危险边界仍清晰；窄窗口与 DPR2 下仍为圆且位置不漂移。
3. **状态闭环：** paused、won、lost、R 后 ready 同组截图；结果来自快照，原因可辨，非 running 状态无开启的技能圈，键位与能力说明仍可见，重试没有旧提示/旧圈/旧缓存。

真实浏览器另验：同时多键移动/施力显示一致；技能圈匹配实际 fieldActive，ready 按施力键仍无开启场圈；松键和失焦后技能圈及时关闭；暂停后主体不漂移且技能圈关闭；重试 runId 变化后及时恢复；超速只警告；低速入港由 runtime 进入 won。方向键/空格滚动抑制由 Agent 3 的输入和页面集成验收。

## 9. 性能预算与后续扩展

以下为**未实测目标，不是承诺**：1200×720 世界、有效 DPR≤2、约20个天体和两个力场，目标60FPS；常见桌面浏览器绘制阶段平均≤5ms、P95≤8ms。物理耗时由 Agent 3 独立记录。

避免每帧创建离屏画布、重生星点或计算静态装饰；可缓存渐变/背景，但主体必须可由完整快照重建。降级顺序：取消渐变/星空 → 减装饰线 → 限DPR；不得缩技能圈、漏危险体或删关键状态。报告注明浏览器、窗口、DPR、开发/生产构建与实测/未测；没有测量则写“性能预算未实测”，没有真人双人试玩则明确待验证。

未来 WebGL 可替换 createRenderer/CanvasRenderer 内部；FrameSnapshot 是主体数据、GameEvent 是反馈、visualTimeSeconds 是纯视觉时钟、runId 是跨局缓存边界。流线、粒子、尾迹、黑洞和 HUD 均应留在渲染层；新增数据走契约升级，不访问模拟器内部。

当前无关键契约阻塞。背景使用 levelId 稳定哈希；`src/style.css` 由 Agent 2 维护、Agent 3 在 main.ts 导入，均已由三 Agent 接口协议冻结。
