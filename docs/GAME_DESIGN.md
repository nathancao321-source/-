# THE LAST ARK · 游戏设计（细化版）

> 状态：2026-10-18。当前仓库是**单屏垂直切片**：四关可运行，33 个自动测试通过。本文把已验证实现、已定案设计、待实现架构分开写，避免把规划当成现状。
>
> 本次先处理两个手感问题：**飞船/天体移速偏大**，以及**飞船离开力场范围后速度过高、难以追回**。调整后的数值见第 5 节；摄像机自动缩放、玩家惯性移动与天体阻尼是下一阶段设计，已在本文给出接口和验收条件。

---

## 1. 世界观与第一原则

人类最后的方舟不能由玩家驾驶。两名玩家操作的不是星球，也不是飞船，而是**高维文明投射在二维宇宙中的引力场控制中心**。

因此：

- 蓝、金节点没有质量、没有惯性、不接收普通天体引力，也不承受反作用力。
- 节点的移动由独立的控制动力学决定；节点之间、节点与天体之间不发生碰撞。
- 方舟、行星、陨石、太阳仍遵循同一套牛顿式引力与惯性规则。
- 蓝场吸引、金场排斥都能对方舟做功：加速、减速、转向、进入束缚轨道。
- 不禁止轨道捕获，不为了关卡平衡篡改万有引力的基本性质。
- 技能开关不阻断节点移动：按一次开启、再按一次关闭，移动中始终可施力。

一句话：**玩家改变的是空间里的力场位置，不是天体的属性。**

渲染与叙事也服从这一点：节点是能量投影，不是实体小球；力场应表现为空间本身的形变，而不是两张跟随节点的彩色贴图。

## 2. 游戏路线

| 阶段 | 场景 ID | 内容 | 出口 |
| --- | --- | --- | --- |
| 标题 | `title` | 章节选择、继续、设置 | 进入 Level 0 |
| Level 0a | `tutorial_part_1` / `first-contact` | 移动、吸引、排斥、双场叠加；零输入也能漂入跃迁门 | 进入跃迁门 → Level 0b |
| Level 0b | `tutorial_part_2` / `moving-world` | 可移动行星、行星自身引力、低速泊入告别港 | 泊入 → Level 1 |
| Level 1 | `solar_system` / `solar-exodus` | 太阳引力、日冕、行星共振、冲击波、门锁 | 4/4 共振 + 低速进入冥王星之门 |
| Level 2 | `black_hole` / `beyond-horizon` | 不可推动黑洞、伽马喷流、潮汐残骸、银河出口 | 绕开视界 + 低速出口 |
| 休整 | `galactic_rest` | 银河边缘信标，无敌人、无生成器 | 返回章节选择 |

设计边界：

- 主线关卡完整加载；只有无限模式才使用区块流式加载。
- 当前不实现 Level 3 之后的新内容；太阳、黑洞、行星仍由配置驱动，不在物理核心中写死名称。
- 每一关都必须能通过纯物理与合法输入通关；禁止直接改位置、速度或阶段的“通关脚本”。

## 3. 坐标、世界与摄像机

### 3.1 世界坐标是唯一事实来源

- 所有实体使用世界坐标 `position` / `velocity`，单位分别为 px、px/s。
- 物理模拟只读世界坐标，不读 Canvas 像素、屏幕 UV、窗口尺寸或 DPR。
- 摄像机、缩放、窗口比例只影响显示，不得改变模拟。
- 背景星点、星云、尘埃必须绑定世界坐标；摄像机移动时整体变换，不能出现“节点能量云与背景各自漂移”的图层错位。
- 当前单屏关卡仍以 1200 × 720 逻辑世界为构图基准；世界边界是关卡规则，不是渲染限制。

### 3.2 摄像机跟随（下一阶段接口）

目标：始终让**方舟、P1、P2**三者同时可见；玩家允许走出当前画面，但不允许因此丢失。

- 构图组 = 方舟 + 两个节点。
- 跟随中心取三者的速度前瞻包围盒中心，前瞻约 0.4 s。
- 屏幕边缘不是物理边界；只有关卡显式配置 `missionBounds` 时才限制方舟。
- 缩放规则：
  - 三者包围盒即将超出安全边距时自动拉远；
  - 向画面内收拢时自动拉近；
  - 拉近有上限（例如 1.6×，保持像素细节）；
  - 拉远原则上无硬上限，但设置最小可读缩放（例如 0.25×），低于该值时以边缘指示器补充信息；
  - 缩放使用指数平滑，禁止逐帧跳变。
- 离屏指示：玩家离屏显示 P1/P2 方向箭头与距方舟距离；目标离屏显示绿色方向提示。
- 小地图显示当前已加载实体、任务目标与摄像机范围。
- 摄像机平滑不得造成物理位置、碰撞判定或入港判定的任何变化。

**当前代码状态**：渲染器使用固定 letterbox 的 1200 × 720 视口，节点被夹在世界内，方舟越界即失败；摄像机跟随、自动缩放、边缘指示和小地图尚未实现。实现时以本节为契约，不改动物理核心。

### 3.3 “飞船飞出范围”的可恢复性

这里的“范围”有三层，处理方式不同：

1. **离开力场半径**：物理上必然发生，方舟保持真实惯性；通过更早的轨迹预测、更低的全局速度上限和节点机动性来让玩家追得回来。
2. **离开镜头**：由摄像机自动缩放与边缘指示解决，不应触发失败。
3. **离开关卡允许区**：只有关卡显式配置的 `missionBounds` 或既有 `out-of-bounds` 规则才失败；失败前必须给出清晰的预测终点。

## 4. 物理核心（保留并明确）

### 4.1 固定步长

- `fixedDt = 1/60 s`；浏览器帧率只影响渲染次数。
- 单帧墙钟 delta 上限 0.1 s；最多补算 `maxCatchUpSteps = 6`，超额积压丢弃。
- 暂停、失焦、重试、切关时清空累计器；后台不追赶。
- 所有玩家移动、天体积分、碰撞检测都只在这个固定步长内发生。

### 4.2 力场

对单个源：

```text
a = s · strength · d / (r² + ε²)^(3/2) · max(0, 1 − r/R)²
```

- `d = source − target`，`r = |d|`，`R` 为作用半径，`ε` 为软化距离，`s = +1` 吸引、`s = −1` 排斥。
- 每个源先限幅到 `field.maxAcceleration`。
- 合向量乘 `motionResponse`，再限幅到 `physics.maxTotalAcceleration`。
- 同一时刻先计算所有天体的加速度，再统一积分；禁止边遍历边读取新位置。
- 速度每步限幅到 `physics.maxBodySpeed`。

### 4.3 天体引力与弹弓

- 天体引力使用同一个函数，`s = +1`；引力强度、半径、软化与响应系数由关卡配置。
- 大天体可以有很小的 `motionResponse`（例如太阳 0.02），仍能被玩家微弱推动；黑洞用 `motionResponse = 0` 且不接受力场。
- 不禁止束缚轨道、不施加“轨道捕获补偿”；引力弹弓是自然结果。
- 速度上限是游戏规则，不是对引力的修改；它保证长时间加速不会把飞船变成不可读的高速炮弹。
- 本次调低了大型天体的近距离加速度上限（见第 5 节），让弹弓有效但不过分。

### 4.4 碰撞、入港、失败

- 方舟与危险天体使用相对运动扫掠圆，避免高速穿透。
- 黑洞使用 `consumeRadius` 中心距离判定。
- 方舟完整碰撞圆进入空间港且速度 ≤ `maxEntrySpeed` 才胜利；完整入港但超速只警告，可以港内减速。
- 失败优先级：`consumed > collision > out-of-bounds`；失败优先于胜利。
- 非方舟天体离开世界仍保留在模拟中；只有方舟越界才失败（当前单屏关卡）。

### 4.5 非飞船天体的稳定机制（设计已定，尚未实现）

目的：玩家推走的陨石/行星不应无限飞走，但飞船必须保留真实惯性。

| 实体 | 规则 |
| --- | --- |
| ship | 不添加任何自动阻尼；保持惯性、引力与外力 |
| player | 使用独立的加速度移动与辅助制动（见 6.2） |
| free asteroid | 离开有效力场后，玩家造成的速度按半衰期 0.8–1.5 s 指数衰减 |
| tutorial planet | 离开力场后平滑减速，保持当前位置，不弹回出生点 |
| orbiting planet | 保留基础轨道运动；只衰减“玩家造成的速度扰动” |
| black hole | 不接受玩家移动作用 |

实现约束：

- 力场正在作用时不叠加游戏化阻尼；离开力场后平滑启动。
- 存在显著环境引力时不直接清零总速度。
- 阻尼与固定步长结合：`v *= 0.5 ** (dt / halfLife)`。
- 速度低于阈值可吸附到静止，避免长期微小漂移。
- 再次进入力场可立即恢复正常受力。
- 半衰期放在实体配置中，禁止按名称硬编码。
- 必须保留“关闭游戏化阻尼”的调试开关，用于比较纯惯性模式。

## 5. 速度与尺度预算（本次调整）

### 5.1 调整前后

| 参数 | 调整前 | 调整后 | 目的 |
| --- | --- | --- | --- |
| `maxBodySpeed`（0a/0b） | 220 | 150 | 限制长期加速后的失控速度 |
| `maxBodySpeed`（1/2） | 240 | 160 | 保留关卡差异，仍可读 |
| `maxTotalAcceleration` | 180 | 140 | 降低双场叠加时的瞬时爆冲 |
| 方舟初速 0a / 0b / 1 / 2 | 52 / 76 / 58 / 62 | 40 / 60 / 48 / 52 | 开局更从容，给判断留时间 |
| 玩家移速 0a / 0b / 1 / 2 | 300 / 300 / 310 / 310 | 240 / 240 / 250 / 250 | 节点更稳，仍快于飞船上限 |
| 玩家力场源限幅 0a / 0b / 1 / 2 | 110 / 120 / 115 / 118 | 90 / 95 / 95 / 108 | 降低近场猛推；2 关保留更强制动 |
| 行星引力源限幅 | 22 | 18 | 减少被行星“甩飞” |
| 太阳/黑洞引力源限幅 | 38 / 44 | 30 / 34 | 弹弓仍成立，但不轻易到上限 |
| 伽马喷流加速度 | 52 | 38 | 避免借喷流一次冲到高速 |

### 5.2 可读性基准

以 1200 × 720 逻辑世界为参照：

- 方舟常规巡航 40–60 px/s，穿越一屏约 20–30 s。
- 方舟硬上限 150–160 px/s，穿越一屏约 7.5–8 s。
- 节点上限 240–250 px/s，始终快于方舟，能重新占位。
- 160 px/s 的方舟在 285–300 px 力场内，由 95 px/s² 的斥力可在约 1.5–2 s 内降到 90 px/s 以下；测试 `tests/speed.test.ts` 覆盖该恢复场景。
- 飞船离开力场后不会自动减速；这是有意的真实惯性。玩家应借助预计轨道线提前站到船头，而不是等飞船飞到边缘才追。

### 5.3 自动护航复测

| 关卡 | 零输入 | 自动护航 | 入港速度 |
| --- | --- | --- | --- |
| `first-contact` | **won** 21.0 s | won 21.0 s（零输入） | 40.0 |
| `moving-world` | lost / collision 6.4 s | **won 13.2 s** | 47.7 |
| `solar-exodus` | lost / collision 8.7 s | **won 24.4 s** | 35.4 |
| `beyond-horizon` | lost / consumed 7.8 s | **won 13.1 s** | 64.7 |

`beyond-horizon` 的 64.7 距 65 的上限很近，说明自动路线只在最后约 0.4 s 才完成制动。真人试玩时应更早站在出口前方；后续可略微提高该关斥力或延长接近段，而不是提高全局速度上限。

## 6. 玩家控制

### 6.1 已实现

- P1：`WASD` 移动，`F` 切换吸引；P2：方向键移动，`Enter` 切换排斥。
- 力场是**按一次开、再按一次关**，不是长按；移动中始终可以开关。
- 非 `running` 状态强制关闭力场显示；暂停/失焦清空按键。
- 两名节点不参与碰撞、不互相施力、不被天体吸引。

### 6.2 目标手感：有限加速度的连续移动（下一阶段）

当前实现仍是“输入方向 × 移速”的位置更新，存在瞬间启动/停止/反向。目标模型：

```text
targetVelocity = direction * moveSpeed
delta = targetVelocity - velocity
velocity += clamp(delta, acceleration * dt)      // 每次固定步只允许有限变化
position += velocity * dt
```

无输入时使用辅助制动（`braking`），而不是瞬间归零：

- 约 0.4 s 达到常规最高速度；
- 松开输入后约 0.6 s 平滑降至接近静止；
- 反向输入先减速、再反向加速，没有瞬时调头；
- 移动结果与渲染帧率无关；
- 按住技能不影响移动；
- `moveSpeed`、`acceleration`、`braking` 全部由配置控制；
- 蓝、金节点先使用相同参数，试玩后再决定是否差异化。

建议配置量级（以当前世界尺度）：`moveSpeed 240–260`、`acceleration 650–800 px/s²`、`braking ≈ moveSpeed / 0.6`。这些是起点，不是最终手感结论。

## 7. 场景状态机

分离 **Scene（内容）** 与 **GamePhase（本局状态）**：

```text
SceneId: title | tutorial_part_1 | tutorial_part_2 | solar_system | black_hole | endless
GamePhase: ready | running | paused | failed | completed
```

合法转换：

```text
title --选择--> 场景 + ready
ready --Space--> running
running --Space/失焦--> paused --Space--> running
running --危险规则--> failed
running --目标完成/转场触发--> completed
failed/completed --R--> 当前场景检查点 + ready
任意游戏场景 --Esc/M--> 章节选择
running --场景触发器--> 目标场景 + ready
```

约束：

- 状态由运行时判定，渲染器只读快照。
- 场景切换必须由关卡显式触发条件驱动，不能读取屏幕坐标。
- 切场景清空事件、输入、轨迹缓存、检查点与镜头平滑状态。
- `runId` 变化是清理所有跨局缓存的唯一依据；`tick = 0` 不能替代。

### 检查点与重试

- `R`：从当前关初始配置重开。
- `Shift+R`（目标）：从最近检查点重开。
- 第 1、2 关的检查点建议放在“进入行星链/潮汐走廊”处，减少重复前戏。
- 重试后不得残留力场开启、旧轨迹、旧提示或旧波纹。

## 8. 实体模型

统一实体，能力由配置表达：

| 类型 | 默认运动 | 发出引力 | 碰撞 | 受玩家力场 | 备注 |
| --- | --- | --- | --- | --- | --- |
| `ship` | dynamic | 可配置 | 自身为受检主体 | 1 | 绝不加自动阻尼 |
| `player` | 独立控制动力学 | 否 | 无 | 0 | 高维投影，不参与天体积分 |
| `asteroid` | dynamic | 可配置 | hazard | 1 | 可加稳定阻尼 |
| `planet` | dynamic | 是 | hazard | 0.15–0.25 | 可被缓慢推动 |
| `star` | dynamic | 是 | hazard | 0.02 | 可被微弱推动 |
| `black_hole` | static | 是 | capture | 0 | 不可推动 |
| `station` | static | 否 | 无 | 0 | 目标 |
| `wormhole` | static | 否 | 无 | 0 | 转场触发器 |
| `background` | 强制静止 | 否 | 无 | 0 | 仅显示 |

关键区分：

- **可动态受力**：ship、asteroid、planet、star。
- **有引力但基本固定**：black_hole、station、wormhole。
- **仅显示**：background 层。
- **触发切换**：wormhole、station、显式区域。

太阳可微弱推动、黑洞不可推动，必须通过 `motionResponse` / `receivesPlayerFields` 等配置实现；物理核心不得出现按名称判断的分支。

## 9. 关卡机制与目标

### 9.1 触发器

关卡数据可声明：

- 实体进入/停留在圆形或矩形区域；
- 以不超过指定速度进入目标（完整包含判定）；
- 某天体被移动到指定位置；
- 方舟经过某条轨道带；
- 某阶段完成后显示提示；
- 虫洞/空间站触发场景转场。

所有触发器按 ID 去重，只读世界状态；不读取屏幕坐标。

### 9.2 当前四关核心

| 关卡 | 核心机制 | 目标 |
| --- | --- | --- |
| 0a | 移动、吸引、排斥、双场叠加 | 进入跃迁门，不限速 |
| 0b | 行星受力移动、行星引力、制动 | 避开行星，≤ 48 泊入 |
| 1 | 太阳引力、四道共振、冲击波、门锁 | 4/4 共振 + ≤ 60 进口 |
| 2 | 不可推动黑洞、潮汐走廊、伽马喷流 | 绕开视界 + ≤ 65 出口 |

### 9.3 效率评价（设计，待实现）

通关后显示：

- 完成时间；
- 方舟实际航行距离；
- 三星阈值（由关卡配置，不写死全局规则）。

原则：

- 不增加强制倒计时失败；玩家可以慢慢完成。
- 评分只影响展示与记录，不影响胜负。
- 无限探索模式不启用限时评分。
- 建议评分 = `时间分 × 距离分`，避免“绕远路但很快”或“直线磨蹭”单指标刷分。

### 9.4 双人合作测试场景（设计，待实现）

可从开发模式启动的独立场景：

- 方舟向空间港运动，航线附近有 2–3 颗真实受力的移动陨石。
- 蓝场可以牵引方舟维持航线，也可以把陨石拉离航道。
- 金场可以推开逼近的陨石，也可以为方舟制动。
- 两股力同时作用于方舟与陨石，存在相互干扰与时机选择。
- 不检查“两人是否都按过技能”，不设置只有金球能触发的隐藏机关，不为制造合作而修改物理规则。
- 至少给出一条可复现的合作路线，用自动护航/回放记录验证；但不能据此宣称双人一定优于单人，仍需真人试玩。

设计建议：用几何与节奏制造分工，而不是锁死操作。例如让一颗陨石从侧上方进入蓝场范围，同时方舟需要在出口前减速——蓝场继续修正航向、金场先去船头制动，之后再转向清理陨石。

### 10.2 必测项

1. 静止起步没有速度突变。
2. 松开方向键平滑减速；反向输入不瞬移。
3. 按住 F / Enter 时仍可自由移动。
4. 蓝场可以吸引、减速、捕获方舟；金场可以推动方舟与陨石。

6. 摄像机移动/缩放不改变物理、背景与节点不漂移。
7. 飞船飞出镜头时有方向指示，摄像机自动拉远；不因镜头而失败。
8. 陨石离开力场后逐渐减速；飞船不受该阻尼影响。
9. 教学关、太阳关、黑洞关无回归。
10. 成功后正确显示时间、距离与星级。
11. 重试/切关后无旧场圈、旧轨迹、旧提示。

- 扫掠碰撞、完整圆入港、边界；

  - 各关 `maxBodySpeed ≤ 160`、初始方舟速度 ≤ 60；

## 11. 性能架构

- 固定步长物理，渲染与物理分离。
- 只渲染摄像机可见区域内的实体；不可见实体仍可参与物理（主线关卡数量可控）。
- 无限模式预留区块接口：按空间区块加载/卸载天体，不一次生成全宇宙。
- 引力计算禁止全宇宙两两配对；主线关卡使用显式天体列表，无限模式使用局部邻域。
- 确定性随机：同一 seed + 区块坐标生成同一星域；渲染装饰可用关卡 ID 的稳定哈希生成。
- 离线/缓存二维纹理与背景层；避免每帧创建离屏画布、重新生成星点或昂贵分形噪声。
- 降级顺序：减少背景细节 → 减少装饰 → 限制 DPR；不得降低碰撞/目标可读性。

## 12. 验收与已知限制

### 已实测

- TypeScript 类型检查、33 个 Vitest 测试、生产构建。
- Edge headless 实际渲染四关画面，console 无错误。
- 力场按一次开启/再开启关闭；预计轨道线随力场弯曲；章节菜单可切换关卡。
- 本次速度调整后的自动护航结果见 5.3。

### 尚未验证 / 未实现

- **玩家惯性移动**（第 6.2 节）：当前仍是直接位置更新，需修改输入/物理并补测试。
- **摄像机自动缩放、小地图、边缘指示**：当前是固定单屏 letterbox。
- **非飞船天体阻尼**：设计已定，尚未实现。
- **效率评分/三星**：尚未实现。
- **合作测试场景**：尚未实现独立场景。
- **真人双人同键盘手感**、硬件 ghosting、低端机性能。
- **无限模式**：仅预留架构，不在本阶段实现。

### 调参优先级

1. 真人试玩确认节点移速 240–250 与方舟上限 150–160 是否仍然偏快/偏慢。
2. 观察 `beyond-horizon` 出口前 64.7 的制动余量，优先调整该关斥力或接近段，而不是全局提速。
3. 若玩家仍追不上飞船：先提高节点加速度/制动，或扩大力场半径；不要给飞船加自动阻尼。
4. 若天体被推得太远：实现第 4.5 节阻尼，而不是降低飞船惯性。

## 13. 不可违反的约束

- 纯 2D、Canvas 2D / TypeScript；不引入 Three.js 或三维场景。
- 物理只在世界坐标与固定步长中运行；屏幕、缩放、DPR 不影响模拟。
- 节点不是天体：不参与引力、碰撞、反作用力。
- 飞船不加自动阻尼；不得用“隐藏弹簧”把它拉回。
- 不禁止束缚轨道与引力弹弓。
- 不直接改位置/速度/阶段来伪造通关。
- 关卡差异通过配置表达，不在物理核心按名称硬编码。
- 已有四关必须继续可通关；视觉升级不得改变胜负判定。
